กับดักของระบบนี้

ตารางไม่อัปเดตเอง ต้องกดแถบ 🔔 มีข้อมูลใหม่ — กดเพื่อโหลด ที่ลอยอยู่ล่างจอ (ตั้งใจทำแบบนี้เพื่อลดค่าโหลดข้อมูล) · แท็บแผนรับสินค้าอัปเดตเองทันที ต่างจากแท็บอื่น
ไฟล์ใหญ่เกิน 1,000 แถว ขั้นตอนนำเข้าอ่านข้อมูลเดิมได้สูงสุด 1,000 แถว — ไฟล์ที่ใหญ่กว่านั้นแถวส่วนเกินอาจถูกนับว่า “ไม่พบในระบบ” หรือสถานะถูกคำนวณใหม่ทับของเดิม แบ่งไฟล์เป็นก้อนเล็กปลอดภัยกว่า
สถานะ ERP ที่ระบบไม่รู้จัก ค่าอื่นที่ไม่ใช่ รออนุมัติ / อนุมัติเรียบร้อย / สำเร็จ / โมฆะ จะถูกตั้งเป็น “อยู่ระหว่างสั่งซื้อ” ทั้งหมด — เจอสถานะเพี้ยนให้ดูค่าในไฟล์ต้นทาง
ERP ส่ง “สำเร็จ” แต่ของยังไม่ครบ ระบบไม่ยอมให้เป็น “เข้าคลังแล้ว” จะตั้งเป็น “รอนำส่งเข้าคลัง” แทน — นี่คือพฤติกรรมที่ถูกต้อง ไม่ใช่บั๊ก
หมายเหตุในไฟล์ไม่ถูกอ่าน ตั้งใจไม่อ่าน เพื่อคงหมายเหตุที่พิมพ์ไว้ในเว็บ — จดหมายเหตุในเว็บได้เลย ไม่หาย
ประกาศเด้งซ้ำ “ไม่แสดงอีกวันนี้” ผูกกับเวอร์ชันประกาศ — จัดซื้อแก้ประกาศใหม่จะเด้งใหม่กับทุกคน (ตั้งใจ)
ราคาเป็น ¥ ทุกจุดหน้านี้ไม่แปลงสกุลเงิน — ตัวเลขที่เห็นคือหยวน

เซ็นชื่อ ≠ อนุมัติ หัวหน้า / ผู้บริหาร

⚠️ เป็น 2 ปุ่มแยกกัน — ✍️ เซ็นชื่อ ใส่ชื่อในช่องลงนามของใบพิมพ์ · ✅ อนุมัติ เดินสถานะ · อนุมัติแล้วลืมเซ็น ใบ PDF จะไม่มีชื่อ · ผู้บริหารเซ็นก่อนหัวหน้าไม่ได้ และหัวหน้ายกเลิกลายเซ็นไม่ได้ถ้าผู้บริหารเซ็นแล้ว

🔍 ปุ่มตรวจสอบ ตรวจอะไร

เป็นการตรวจด้วยกฎในเครื่อง ไม่ต้องรอเน็ต ผลติดเป็นป้ายรายแถว

ป้ายเจออะไร
🔴 ต้องตรวจ จำนวนหรือราคา ≤ 0 · SKU มีหลายซัพพลายเออร์แต่ไม่เลือก · รายการซ้ำ (SKU+ซัพพลายเออร์ซ้ำแถวอื่น) · ไม่พบ SKU ในข้อมูลกลาง · ยอดรวมไม่ตรงสูตร · เรทหยวนหลุดช่วง 4.0–6.0
⚠️ พิจารณา มี SKU แต่ยังไม่มีราคามาตรฐานของซัพพลายเออร์นั้น · ราคาต่างจากราคากลาง
✅ ผ่านไม่เจอข้อสงสัย
ℹ️ ค่าความคลาดเคลื่อนของราคาตั้งไว้ที่ 0 — ต่างจากราคากลางแม้สตางค์เดียวก็ขึ้น ⚠️ ฉะนั้นจะเจอเตือนบ่อย อย่ากดผ่านอัตโนมัติ ให้ดูก่อนว่าราคาขึ้นจริงหรือพิมพ์ผิด · ถ้าราคาขึ้นจริง ควรอัปราคากลางให้ตรง (อัปที่ Purchase Board หรือแท็บ 🗄️ ข้อมูลกลาง)

💡 ⏪ ย้อนกลับ 1 ขั้น มีให้ตามบทบาท — จัดซื้อย้อน “รอหัวหน้า → ยังไม่ส่ง”, หัวหน้าย้อน “รอผู้บริหาร → รอหัวหน้า”, ผู้บริหารย้อน “อนุมัติ → รอผู้บริหาร” · ใบที่อนุมัติแล้วและออกเลข PO ไปแล้ว ย้อนไม่ได้ ต้องลบเลข PO ออกก่อน

กับดักของระบบนี้

แก้ไขใบ = ลายเซ็นหายหมด กดบันทึกหลังแก้ไข ระบบล้างลายเซ็นทุกช่อง ล้างเหตุผลที่ตีกลับ และตั้งสถานะกลับเป็น “ยังไม่ส่ง” → ต้องส่งอนุมัติและเซ็นใหม่ทั้งวงจร · แก้คำผิดเล็กน้อยก็เสียรอบอนุมัติ ตรวจให้ครบก่อนส่ง
ปุ่มบันทึกกดไม่ได้ยังไม่กด 🔍 ตรวจสอบ PR — บังคับทุกครั้ง
บันทึกแล้วหัวหน้าไม่เห็นบันทึก = ร่างส่วนตัว ต้องกด 📨 ส่งอนุมัติ อีกทีจึงเข้าคิว
เลข PR ซ้ำมีแถบเตือนแดงบนสุด + ป้าย ⚠️ เลขซ้ำ + แถวพื้นแดง · ระบบหาเลขใหม่ให้เองตอนสร้าง แต่ถ้าพิมพ์เลขเองซ้ำก็ซ้ำได้
ไม่มีช่องไหนบังคับกรอกหัวใบ เลข PR / วันที่ / ผู้ขอซื้อ / แผนก ปล่อยว่างแล้วบันทึกได้ — ต้องระวังเอง
นำเข้า Excel ข้อมูลกลาง = ทับทันทีไม่มีพรีวิว ราคาเดิมถูกทับเลย — ตรวจไฟล์ก่อนเลือก

กรอกหัวคำขอ จัดซื้อ

แท็บ 📋 รายการคำขอ → + สร้างคำขอ · ช่องที่มี ★ บังคับ: กำหนดชำระ · จ่ายในนาม · ช่องทางการโอน

💡 ช่องทางการโอน = เงินไปทางไหน (JMF / Ksher / ธนาคาร) · ช่องทางการชำระเงิน = เงินออกจากบัญชีไหนของเรา — เลือกช่องทางที่เคยใช้ ระบบเติมเลขบัญชีเดิมให้เอง · เลขบัญชีใส่ได้หลายบรรทัด
2

ใส่รายการที่จะจ่าย จัดซื้อ

ปุ่มกลางฟอร์ม
＋ ดึงงวดจ่าย 📄 ดึงจากใบปะหน้า＋ เพิ่มรายการเอง
ปุ่มใช้เมื่อไหร่
＋ ดึงงวดจ่ายปกติใช้อันนี้ — เลือกงวดที่ยังไม่เคยถูกยื่น ติ๊กแล้วกดเพิ่ม
📄 ดึงจากใบปะหน้าทำใบปะหน้าไว้แล้ว → ดึงทั้งใบมาทีเดียว เติมจ่ายในนาม/ช่องทาง/กำหนดชำระให้เอง
＋ เพิ่มรายการเองกรณีพิเศษที่ไม่มีในระบบวางแผน — ต้องพิมพ์ยอดเอง
✅ ดึงงวดมาแล้วไม่ต้องคิดเลขต่อ — ระบบตั้ง สกุลเงินที่โอนจริง ให้เอง งวดที่ระบุไว้ว่าโอน USD จะได้ยอด USD ที่ระบบวางแผนคำนวณไว้แล้ว ไม่ใช่ยอดหยวนมาแปลงเอง และเติมเรทให้ด้วย
💡 แถวที่ดึงมาล็อกตัวเลขไว้กันพิมพ์ผิด — ถ้าต้องแก้จริง ๆ กด 🔓 ท้ายแถว (แถวเป็นสีเหลือง = แก้มือ) · กด 🔒 เพื่อคืนค่าจากระบบ

ใส่เหตุผล แล้วส่ง จัดซื้อ

ท้ายฟอร์ม
ปิด💾 บันทึกร่าง 📤 ส่งอนุมัติ
💾 บันทึกร่างเก็บไว้ทำต่อ ยังไม่ถึงใคร แก้ได้ตลอด
📤 ส่งอนุมัติเข้าคิวผู้บริหารโดยตรง — หลังส่งผู้ยื่นแก้ไม่ได้ จนกว่าจะถูกตีกลับ · เหตุผลการขออนุมัติ ★ บังคับกรอกก่อนส่ง เขียนให้ผู้อนุมัติตัดสินใจได้ทันทีโดยไม่ต้องถามกลับ

ผู้บริหารอนุมัติ ผู้บริหาร

ส่งแล้วเข้าคิวทันที — ดูที่แท็บ ⏳ รออนุมัติ (มีตัวเลขแจ้งเตือนบนแท็บ) → กด 👁 ดู

ท้ายหน้าดูคำขอ — ผู้บริหาร
ปิด🖨️ พิมพ์ใบขออนุมัติ ↩️ ตีกลับ👑 อนุมัติจ่าย
💡 ตีกลับต้องใส่เหตุผล — มีเหตุผลสำเร็จรูปให้กด (ยอดไม่ตรง / ไม่มีหลักฐาน / ขอเลื่อนกำหนด) ผู้ยื่นจะเห็นเป็นกรอบแดงในคำขอ
5

แจ้งโอนเงิน จัดซื้อ / บัญชี

เปิดคำขอที่อนุมัติแล้ว → 📢 แจ้งโอนเงิน → ระบบสร้างข้อความให้ตามช่องทางที่เลือกไว้

ช่องทางการโอนได้ข้อความแบบต้องกรอกเพิ่ม
JMF CARGOแจ้งโอน SCB — ยอดชำระ + เลขบัญชีไม่ต้อง (มีให้แล้ว)
Ksher Payment Co.Ltd.เติมเงินเข้าระบบ Ksher — ยอดเติม + เรท + ยอดเดิมยอดเดิมในระบบ · ชื่อผู้ใช้ Ksher
ธนาคาร (SWIFT Code)โอนต่างประเทศ — บัญชีปลายทาง + SWIFTชื่อ/เลขบัญชี/ที่อยู่ผู้รับ · ธนาคารปลายทาง + SWIFT
💡 กรอกเสร็จกด 💾 บันทึกข้อมูลแจ้งโอน — ครั้งหน้าเปิดคำขอเดิม ข้อมูลกลับมาครบ · ได้ทั้งข้อความคัดลอก และการ์ดรูปดาวน์โหลด · เลขบัญชี JMF / Ksher ไม่ถูก แก้ที่ ⚙️ ตั้งค่าบัญชี แล้วกด ✔ บันทึก & ใช้กับใบนี้

แนบเอกสาร แล้วปิดงาน ทุกบทบาท

ปุ่ม 📎 อยู่ท้ายทุกแถวในตาราง — กดได้เลย ไม่ต้องรออนุมัติ และไม่ต้องเปิดคำขอ (มีไฟล์แล้วปุ่มจะเป็นสีเขียวพร้อมจำนวน)

แนบตอนไหนแนบอะไร
ตอนยื่นคำขอใบเสนอราคา · Invoice · ใบแจ้งหนี้ — ช่วยให้อนุมัติได้เร็ว ไม่ต้องถามกลับ
ตอนโอนเงินแล้วสลิปโอนเงิน — โอนหลายบัญชีก็แนบหลายใบได้
✅ ปุ่มเขียว 💾 บันทึก + ยืนยันจ่ายแล้ว ขึ้นเฉพาะคำขอที่อนุมัติแล้ว = แนบสลิปและปิดงานในคลิกเดียว · ใส่ได้ทั้งรูปและ PDF หลายไฟล์ หรือวางลิงก์ Google Drive · ไฟล์ต้องไม่เกิน 10 MB ต่อไฟล์

💱 สกุลเงินและเรท — ส่วนที่พลาดง่ายที่สุด

ระบบนี้ไม่คิดเลขซ้ำ — ดึงตัวเลขที่ระบบวางแผนจ่ายเงินคำนวณไว้แล้วมาใช้ตรง ๆ ยอดจึงตรงกับใบปะหน้าที่เซ็นกันไปแล้วทุกสตางค์

¥ CNY · หยวนจีน $ USD · ดอลลาร์สหรัฐ ฿ THB · บาทไทย ← ป้ายนี้ขึ้นทุกที่ที่มีตัวเลข
เห็นได้ที่แสดงอะไร
ตารางรายการคำขอคอลัมน์ สกุลเงิน อยู่ก่อนช่องยอด — กวาดตาดูทั้งหน้าได้ทันที · ใบที่แปลงสกุลมีบรรทัดเล็ก ← CNY บอกต้นทาง
ตอนกรอกฟอร์มแถบสีใต้ปุ่มดึงงวด บอกว่า “คำขอใบนี้จ่ายเป็นสกุลอะไร ยอดเท่าไหร่ ตั้งต้นจากบิลสกุลไหน”
หน้าดูคำขอ (👁)ป้ายเต็มข้างเลขคำขอ + ช่อง สกุลเงินที่โอนจริง ในแถบข้อมูล
ใบพิมพ์ · ข้อความแจ้งโอนบรรทัด สกุลเงินที่โอน ระบุตัวย่อและชื่อไทย

ช่องเรท 2 ช่อง ต่างกันอย่างไร

ช่องแปลว่าระบบเติมให้เมื่อไหร่
เรทแปลง
กล่องเหลือง “แปลงสกุลเงิน”
 สกุลบิล → สกุลที่โอนจริง
เช่น หยวน → ดอลลาร์		 งวดระบุยอดปลายทางไว้แล้ว → ล็อกช่องนี้ โชว์อัตราแลกให้ดูเท่านั้น · ถ้างวดไม่ได้ระบุ → จำเรทจากคำขอล่าสุดของคู่สกุลนั้นมาเติมให้ แก้ได้
เรท → บาท
กล่องเทา ใต้กล่องเหลือง
 สกุลที่โอนจริง → บาท
เช่น ฿ ต่อ 1 USD		 ดึงจากเรทของงวดในระบบวางแผน · พิมพ์ทับได้ ใช้กับทุกแถว · หรือพิมพ์ทีละแถวในคอลัมน์ เรท ฿
💡 ลบเรททิ้งได้ — ลบแล้วยอดบาทเป็น 0 พร้อมคำเตือน ระบบไม่เติมกลับให้ · อยากได้เรทเดิมคืน กด ↺ เรทตามระบบ · อยากเลิกแปลงสกุล โอนตามบิลตรง ๆ กด ↺ ไม่แปลง
⚠️ ส่งอนุมัติไม่ได้ถ้าไม่มีเรทแปลง — บิลเป็นสกุลหนึ่งแต่จะโอนอีกสกุลโดยยังไม่ใส่เรท ระบบจะไม่ให้ส่ง เพราะยอดโอนจะเป็น 0

กับดักของระบบนี้

ส่งอนุมัติไปแล้ว อยากแก้ ผู้ยื่นแก้เองไม่ได้ — ขอให้ผู้บริหารกด ↩️ ตีกลับ คำขอจะกลับมาแก้ได้ เลขคำขอเดิม
ยอดที่ดึงมาเป็นหยวน แต่ควรเป็นดอลลาร์ ใบที่สร้างไว้ก่อนระบบจะดึงยอด USD เป็น — เปิด ✏️ แก้ไข แล้วกดบันทึกใหม่ ระบบเติมยอดปลายทางจากงวดให้ถูกทันที · ใบใหม่ไม่เจอปัญหานี้
ดึงงวดจ่ายแล้วไม่เจองวดที่ต้องการ งวดนั้นถูกยื่นในคำขออื่นไปแล้ว — ระบบซ่อนงวดที่ยื่นแล้วเพื่อกันจ่ายซ้ำ · ลองล้างตัวกรองวันที่
ปุ่ม 📢 แจ้งโอนเงิน ไม่ขึ้นขึ้นเฉพาะสถานะ อนุมัติแล้ว หรือ จ่ายแล้ว
คัดลอกข้อความไม่ได้เบราว์เซอร์บล็อกการคัดลอกอัตโนมัติ — ลากเลือกข้อความในกรอบแล้วกด Ctrl+C
ตัวเลขบนแท็บ ⏳ รออนุมัติ ไม่ลดหน้านี้ไม่รีเฟรชอัตโนมัติ — กด F5 หรือสลับแท็บกลับมา
อยากลบคำขอที่อนุมัติ/จ่ายแล้ว ผู้บริหารเท่านั้น และต้องพิมพ์เลขคำขอยืนยัน · ไฟล์แนบใน Google Drive ไม่ถูกลบตาม ต้องไปลบเอง
ลืมว่าคำขอไปถึงขั้นไหน เปิดคำขอ → ดูแถบขั้นตอนด้านบน และตาราง 🕘 ประวัติการดำเนินการ ด้านล่างสุด บันทึกทุกการกระทำพร้อมเวลาและชื่อคน
⚠️ กันจ่ายซ้ำ — ก่อนสร้างคำขอใหม่ ให้ค้นเลข PO ในช่องค้นหาก่อนทุกครั้ง ถ้าเจอคำขอเดิมที่ยัง รออนุมัติ อยู่ อย่าสร้างใบใหม่ซ้อน
